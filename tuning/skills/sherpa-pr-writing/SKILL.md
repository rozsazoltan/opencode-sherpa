# Pull request writing

1. Inspect the actual diff and relevant test results before drafting. Describe only changes present in the work.
2. Summarize user-visible behavior and implementation scope. Call out compatibility, migration, or configuration effects when applicable.
3. List validation commands with observed outcomes. Mark checks not run as skipped; never imply they passed.
4. Keep review notes concise and identify known limitations or follow-up work without overstating risk.
5. Follow an existing repository template when one is provided. Do not invent links, issue references, reviewers, or release details.
6. Draft text only unless the user explicitly asks to create or update a pull request and the available integration permits it.
7. Do not commit, push, merge, publish, or deploy as part of drafting.
