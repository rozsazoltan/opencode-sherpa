# Issue writing

1. Separate observed behavior from assumptions. Include only facts supported by the report, repository, or reproduced result.
2. State the problem in a concise title. Describe expected and actual behavior, impact, and a minimal reproduction when known.
3. Include environment details only when relevant and verified. Remove secrets, personal data, and private customer information.
4. Keep proposed causes clearly labeled as hypotheses. Do not present them as confirmed findings.
5. Add actionable acceptance criteria when the requested outcome is clear. Avoid prescribing implementation without evidence.
6. Draft text only unless the user explicitly asks to create or update an issue and the available integration permits it.
7. Do not invent a repository, issue URL, reproduction, command output, or duplicate check.
